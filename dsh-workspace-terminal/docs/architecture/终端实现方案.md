# 终端实现方案（架构与实现）

> 状态：**已实现并验证**（2026-08-29，playwright 实测）。本文档随代码同步更新。

## 1. 概述

把「模拟终端」升级为**真终端**：`xterm.js`（浏览器渲染）+ `node-pty`（宿主真实 shell）+
`WebSocket`。传输走**原始 WS 路由**（`webServer.registerUpgrade('/ws/terminal')`）——
独立插件最快可用路径。

- **能力在宿主**：node-pty 进程跑在 dsh 宿主，浏览器经 WebSocket 实时双向读写。
- **展示依赖工作台**：作为 widget tab 注册进 `dsh-workspace-sidebar` 工作台；
  缺宿主时插件**跳过注册**并告警（见 §7）。

## 2. 架构（实际实现）

```
┌─ 浏览器（client）──────────────────────────────────────────────┐
│  dsh-workspace-sidebar（工作台 widget 宿主）                    │
│   └─ 终端 tab（registerWidget，multi:true）                     │
│       └─ xterm-pane：xterm.js + FitAddon                       │
│           │  WebSocket（同源，带 dsh-auth-* cookie）            │
└───────────┬────────────────────────────────────────────────────┘
            │  ws://<host>/ws/terminal?sessionId&tab&cols&rows
            │  文本帧=终端输入；JSON{type:'resize'}=尺寸
┌───────────▼────────────────────────────────────────────────────┐
│  dsh 宿主（host）                                                │
│  webServer.registerUpgrade('/ws/terminal')                      │
│    ├─ authorize()：Host/Origin 信任 + dsh-auth-* cookie 告警     │
│    └─ PtyManager（node-pty 懒加载，sessionId:tab keyed 隔离）     │
│        └─ spawn shell（$SHELL / powershell.exe / /bin/bash）     │
└────────────────────────────────────────────────────────────────┘
```

## 3. 数据流

| 方向 | 内容 | 通道 |
|---|---|---|
| 输入 | 用户在 xterm 敲键 → `term.onData` → WS 文本帧 | 浏览器 → 宿主 |
| 输出 | pty `onData` → WS → `term.write` | 宿主 → 浏览器 |
| 尺寸 | `term.onResize` → WS JSON `{type:'resize',cols,rows}` → `pty.resize` | 双向 |
| 退出 | pty `onExit` → WS `\r\n[进程已退出 code=N]\r\n` → 关闭连接 | 宿主 → 浏览器 |

容器尺寸变化（窗口缩放 / 分隔条拖动）由 `ResizeObserver` 防抖 **150ms** 后 `fit.fit()`；
并**挂载后立即 RAF fit 一次**（下一帧容器尺寸已定），避免 xterm 先按默认尺寸渲染、
溢出容器导致滚动条闪现。

## 4. 模块职责

| 文件 | 职责 |
|---|---|
| `src/index.ts` | host：`/ws/terminal` 升级路由 + `authorize()` + WS↔pty 桥（输入 / resize / 退出 / 关闭清理）；teardown `disposeAll` |
| `src/pty-manager.ts` | node-pty 生命周期：`createRequire` 懒加载（缺失 → `available=false` 降级）、`sessionId:tab` keyed 会话、open/close/disposeAll |
| `src/client/index.ts` | `__ModuleLoader__.load` 入口：factory 内 require react，把 `apply` / `inject` 交给宿主 |
| `src/client/plugin.ts` | widget 注册：`inject:['workspace']` + `ctx.workspace.registerWidget(...)`；声明式设置（主题 / 字号）；`multi:true` 多开；组装 WS URL |
| `src/client/terminal.tsx` | widget 外层容器（按主题设背景色，包裹 xterm-pane） |
| `src/client/xterm-pane.tsx` | 单个 xterm 面板：实例化 XTerm + FitAddon、CSS 内联注入、双主题调色板、WS 连接、输入 / resize 上报、focus 管理 |
| `scripts/build.mjs` | esbuild：client（iife、打包 xterm、`react` external、`.css`→text）+ host（esm、`node-pty`/`ws` external） |
| `cordis.patch.yml` | 聚合 bundle 注册本插件 + 防双挂载守卫 |

## 5. 鉴权（`authorize`）

见 `src/index.ts` `authorize()`，三道检查：

1. **Host 信任**：`host` 为 loopback（`127.0.0.1` / `localhost` / `::1`）或命中
   `webRuntime.trustedHosts`（防 DNS rebinding）。
2. **Origin 相等**：`Origin` 存在时必须等于 Host（防跨站）。
3. **cookie 存在性**：`dsh-auth-*` 会话 cookie（0.1.2-alpha.1 一次性 token → cookie 后的
   浏览器会话，同源 WS 自动携带）。当前**缺失仅告警不拒绝**——本地开发绕过 `?token=`
   直连页面时 WS 也能连上。

> 当前是存在性检查，未做签名验证（升级方向见 §11）。

## 6. WS 协议

- 文本帧 = 终端输入（`pty.write`）。
- JSON `{type:'resize', cols, rows}` = pty 尺寸（解析失败按普通输入处理）。
- 进程退出：宿主先发 `\r\n[进程已退出 code=N]\r\n`，再关闭 WS。
- 异常关闭：node-pty 不可用 / pty 打开失败 → close code `1011`。

## 7. 多开与会话隔离

- widget 注册 `multi: true`：工作台 TabBar「+」可开**多个终端实例**。
- 每实例用独立 `tab=<instanceId>` 连宿主；host 以 `sessionId:tab` 为 key 隔离 pty →
  **每个实例独立 shell / pty，互不干扰**。
- 当前 `sessionId` 由 client 固定为 `default`，隔离粒度是 `tab`（不跨会话隔离）。

**缺工作台宿主（dsh-workspace-sidebar 未装）**：`apply()` 开头守卫 `if (!ctx.workspace)` ——
跳过注册并 `console.warn` 提示，**不抛错、不崩溃**。此时插件在 dsh 里没有任何可见 UI，
属预期行为（`workspace` 服务由 sidebar 提供，不是 dsh 内置）。

## 8. 决策记录（为什么走原始 WS，不用 Remote 网关 / typert）

| 方案 | 结论 |
|---|---|
| Remote typert **严格 codegen** | 不可行：构建机器是 harness monorepo 一等包的内部 helper（`clientBundle` 624 行），独立插件拿不到 |
| Remote **`ctx.typert.register()` 手动** | 可行但成本高：要手写 generator 输出（schemas + 包反射 + InvocationDescriptors），client 调用方式待验证 |
| **原始 WS 路由**（本方案） | ✅ 最快可用：一个 `registerUpgrade` + node-pty，鉴权自己写 |

**什么时候必须做端点 / 通道**：浏览器无法直接执行宿主侧操作（spawn 进程 / 文件系统 /
服务器逻辑），一旦需要宿主能力或实时双向流，**必须建浏览器↔宿主通道**；纯 client
（渲染 / 设置 / localStorage / 浏览器内状态）不需要。

## 9. 依赖

| 依赖 | 用途 | 备注 |

## 10. 构建 / 安装 / 验证

```bash
pnpm install && node scripts/build.mjs          # 构建（esbuild）→ lib/
dsh plugin --profile web add <本插件目录>        # 安装进 profile
dsh web --no-open --port 57441                   # 启动
# 浏览器开工作台 → 点「终端」tab → 真 shell
```

**验证结果**（playwright）：终端 tab 渲染、xterm 容器出现、屏显真实 Git Bash 提示符、
`echo hello` 输入→shell→输出→xterm 回显成功、零控制台错误。

> 注：验证时因 playwright 拿不到引导 token（无 cookie）临时放行了 cookie 检查；
> 验证后**已恢复**。真实用户流（`/?token=` 签 cookie）下鉴权正常。
